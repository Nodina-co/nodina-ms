# NODINA — Technical SEO audit, 26 October 2026

Scope: the 22 published URLs in https://nodina.com/sitemap.xml (11 FR, 11 EN), the root redirect, robots.txt, sitemap, RSS feed, markdown alternates, structured data, headers and a Lighthouse mobile run on /en/. Source audited in `src/layouts/SiteLayout.astro`, `src/lib/site.ts`, `tools/build-release.py`. Keyword targeting is out of scope (separate research in progress); this report covers whether the technical foundation is in place.

## Addendum, same day

P1 items 1–4 were fixed in the working tree after this audit: 301 redirects for the two retired profile URLs in `public/_redirects`; the font subsetted to Latin and the 400–700 weight range and served as `intertight.woff2` (44 KB, down from 581 KB) with a one-year cache header; all titles now 65 characters or fewer and all descriptions 162 or fewer; manifesto titles name the founder. The vetting pages use a dedicated meta description instead of the hero lead. The TTF is still shipped because the OG image builder renders with it, but no page requests it. `npm run check` passes.

## Verdict

The foundation is strong. Every page has a unique title, unique description, self-referencing canonical, reciprocal FR/EN hreflang, Open Graph and Twitter card tags, a valid JSON-LD graph, exactly one H1 and one `<main>`, and indexable robots directives. The sitemap, robots.txt, RSS feed, llms.txt and per-page markdown alternates are live. www and http redirect with 301. Lighthouse mobile on /en/: Performance 94, Accessibility 95, Best Practices 100, SEO 100.

The gaps are second-order: a 580 KB unsubsetted TTF font that is the main LCP cost, thin Organization schema, two retired URLs that now 404 after being submitted to Google and Bing, titles and descriptions that exceed display limits on a handful of pages, and brand-voice H1s that carry no search terms.

## Findings, by priority

### P1 — fix soon

**1. Retired profile pages were submitted to search engines and now return 404.**
`/fr/profils/` and `/en/engineers/` were in the 9 October sitemap and IndexNow batch (see `reports/submit/2026-10-09-indexnow.md`). They were hidden on 26 October and now return 404 with no redirect. Google Search Console will report them as "Not found (404)" indefinitely, and any links or AI citations pointing at them are dead.
Fix: add 301 redirects in `public/_redirects` to `/fr/selection-des-talents/` and `/en/vetting/` (the pages that absorbed the content), or return 410 if the intent is permanent removal. 301 is the better choice here.

**2. The web font is the main performance cost.**
`/assets/intertight.ttf` is 581 KB, a full variable font with 2,547 glyphs, served as TTF (no WOFF2), preloaded on every page, and served with `max-age=0, must-revalidate` so it is revalidated on every visit. It is the reason Lighthouse flags LCP at 3.0 s on mobile (the H1 is the LCP element and waits on the font). Everything else in the critical path is small.
Fix: subset to Latin + Latin Extended (French diacritics) and convert to WOFF2. Expect roughly 30–50 KB. Serve from `/_astro/` or add a long-lived cache rule for `/assets/*` in `_headers`. This alone should move LCP under 2.5 s.

**3. Titles and descriptions over display limits.**
Google truncates titles at about 60 characters and descriptions at about 155–160 on desktop, less on mobile.

| Page | Title length | Description length |
|---|---|---|
| /fr/blog/ | 79 | 147 |
| /fr/equipes-ai-native/ | 77 | 218 |
| /en/ai-native-teams/ | 70 | 179 |
| /en/blog/ | 69 | 121 |
| /fr/ | 65 | 179 |
| /fr/solutions-ia-sur-mesure/ | 65 | 159 |
| /en/ | 64 | 159 |
| /fr/selection-des-talents/ | 50 | 235 |
| /en/vetting/ | 37 | 197 |
| /fr/contact/ | 32 | 182 |

Not a ranking factor, but truncated snippets lower click-through. Trim the five titles above 65 and the six descriptions above 170. Titles live in `content/site/offers.*.json` and `content/site/*.json`; vetting descriptions reuse `hero_lead`, which is page copy and should get its own meta field.

**4. Manifesto titles are too short and carry no terms.**
"About NODINA" (12 chars) and "À propos de NODINA" (18 chars). This is the only page that mentions the founder, the PhD and the France/US footprint. A title like "About NODINA: AI consulting led by Jean-David Collard | NODINA" would use the space.

### P2 — worth doing

**5. Organization schema is minimal.**
Currently: name, url, logo. Missing: `sameAs` (LinkedIn company page), `address` or `areaServed` (France, United States), `founder` as a `Person` with `jobTitle` and `sameAs`, `contactPoint`, `description`, `knowsAbout`. The logo is an SVG; Google's logo rich result requires PNG, JPG or GIF. Point `logo` at `Nodina_logo/Nodina_Black_logo_952x208.png` published under `/assets/` and use an `ImageObject` with dimensions.
For a consultancy whose credibility rests on one person, a `Person` node linked from Organization.founder and from the manifesto WebPage is the single highest-value schema addition for both Google and AI answer engines.

**6. BlogPosting schema lacks `image` and a human author.**
Google's Article guidelines list `image` as recommended and prefer `author` to be a Person. The OG image already exists per post, so `image: ogImage` is a one-line addition. `dateModified` is hard-wired to `datePublished`; it should come from frontmatter or the publication plan.

**7. No BreadcrumbList.**
Blog posts and offer pages are two levels deep. A BreadcrumbList (Home › Blog › Post) is cheap and gives Google the site hierarchy; it also drives the breadcrumb display in results.

**8. Sitemap lastmod is identical on all 22 URLs.**
Every entry says 2026-10-26 because `modifiedOn` was bulk-updated. Google ignores lastmod when it is not credible. The release builder reads `modifiedOn` from `content/publication.json`; only update it when a page's content actually changes. Consider adding `xhtml:link rel=alternate hreflang` entries to the sitemap as a second hreflang signal (optional, but standard for bilingual sites).

**9. Trailing-slash and index.html redirects are 307.**
Cloudflare Workers Assets issues 307 for `/en` → `/en/`. Search engines treat 307 as temporary and may keep requesting the non-canonical URL. Low impact because internal links all use the trailing slash, but a 301 from the Worker would be cleaner.

**10. x-default points to a 302.**
`hreflang="x-default"` is `https://nodina.com/`, which 302-redirects by Accept-Language with `Cache-Control: no-store`. This is a pattern Google tolerates, and `Vary: Accept-Language` is set correctly. The alternative is x-default = `/en/` (the fallback the Worker uses for non-French browsers). Either is acceptable; the current setup is defensible but means the root URL itself can never be indexed or carry a snippet.

**11. Vetting page is only reachable from the footer.**
`/en/vetting/` and `/fr/selection-des-talents/` are the longest, most substantive pages on the site (924 and 1,079 words) but are not in the main navigation and are not linked from the AI-native Teams offer page body. Internal links from the Teams page ("how we select engineers") would pass authority to the page most likely to rank for selection/vetting queries.

**12. Blog post bodies link only to the contact form.**
Both posts have one internal link, to `/contact/?offer=systems`. Posts about automating processes should link to `/custom-ai-solutions/`. This is the main lever for the blog to support the offer pages.

### P3 — polish

- **Favicon set.** `/favicon.ico`, `/apple-touch-icon.png` and a web manifest all 404. Browsers and Google (which shows favicons in mobile results) request `/favicon.ico` regardless of the `<link rel=icon>`. Add a 48×48 PNG or ICO at the root and an apple-touch-icon.
- **Content-Type on HTML lacks charset.** `text/html` without `; charset=utf-8`. The meta charset covers it, but adding it in `_headers` is free.
- **Thin pages.** Blog indexes are 85 words of body copy. Fine with one post, but once there are several posts, add a short editorial paragraph. Contact pages are 226–231 words, which is normal.
- **Twitter title/description.** Not set; Twitter falls back to og:title and og:description, so this is fine. Only add if card previews need different copy.
- **Color contrast.** Lighthouse flags one contrast failure on /en/. Not SEO, but it holds Accessibility at 95.
- **H1s carry no search terms.** Every H1 is a brand-voice line ("Put AI to work in the business you already run."). Titles and descriptions compensate, so this is not a defect, but when keyword research lands, the H1 and the first paragraph are where target terms need to appear. Flag for the keyword research agent: the title tags are already keyword-bearing; the H1/lead copy is not.

## What the existing tooling already enforces

`tools/check-site.py` runs on every build and checks: one H1, one main, unique titles and descriptions, canonical, og:url = canonical, OG image exists and is declared 1200×630, hreflang matches the route map, JSON-LD present, image alt/width/height, no links to hidden routes, no broken anchors. This is why the fundamentals are clean. It does not check title or description length, Organization schema completeness, or redirects for retired URLs; P1 items 1 and 3 could be added as checks.
